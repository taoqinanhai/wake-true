# 真醒（WakeTrue）

> 把闹钟的终止条件从**瞬时动作**改成**持续状态**——目标不是"把关闭动作做难"，而是让"我真的起来了"这件事可以被系统验证。

当前处于**文档阶段**，尚未开工写代码。

---

## 一句话问题定义

用户可以在**完全没醒**的状态下就让铃声停下来，而系统在那一刻无法区分"他醒了"和"他翻了个身"。
起床包含两个维度——**时间**（在一段时间里持续清醒）和**空间**（真的离开床），系统闹钟一个都没承载。

完整推导见 [`docs/00-问题定义与JTBD分析.md`](docs/00-问题定义与JTBD分析.md)。

## 当前状态

**已定稿的约束**（后续文档都以此为准，改动需同步）

- 只做 **Android**——"响铃后不可一键终止"在 iOS 上不成立
- 关闭条件：**离原点 > 50 米**，固定阈值，**不标定、不容差**；原点取首次启动时手机的当前位置
- P0 只有三件事：**定**（设一个明天的闹钟）／**响**（到点响铃）／**定位关**（走到 50 米外才能关）
- 允许与系统闹钟并存，做"叠加的保险层"，不要求用户放弃原有闹钟

**尚未验证**（都还是假设，不是结论）

- 目标用户画像来自小范围经验推断，**没有做过真实访谈**
- 室内定位精度能否支撑 50 米固定阈值，**未实测**
- Android 后台闹钟在国产 ROM 上的存活情况，**未实测**
- "保持一段清醒能否防住半睡状态"（假设 B），**未验证且可能不成立**

## 下一步

按 [`01-Pre-mortem分析.md`](docs/01-Pre-mortem分析.md) 的预防措施，顺序不能颠倒：

1. **技术验证先行**——精确闹钟 + 前台服务 + 电池白名单 + 国产 ROM 自启动白名单 + 重启恢复；验收必须覆盖"重启一次 + 放一夜 + 低电量"，不认"原生 Android demo 通过"
2. **宿舍实测定位精度**——直接看 50 米固定阈值会不会误判
3. **访谈 10 位可触达的同学/同事**——问行为不问意见；**访谈未完成不进入开发**
4. 用纸质原型问行为意愿；"清醒能否防住半睡"用小组 14 天自用日志验证
